# AutoShiftMaker 基本設計書

## 1. システム構成
- `index.html`: 画面定義、入力UI、インライン初期化スクリプト。
- `app.js`: 画面イベント処理、入力検証、表示更新、状態管理。
- `scheduler.js`: シフト自動作成ロジック。
- `exporter.js`: シフト結果の表形式変換、CSV・TSV生成。
- `milp-scheduler.js`: 業務ルールを混合整数計画モデルへ変換し、解を画面用データへ整形。
- `solver-worker.js`: HiGHS WebAssemblyによる最適化を画面処理とは別スレッドで実行。
- `vendor/highs/`: GitHub Pagesで配信するHiGHSのJavaScript・WebAssembly・ライセンス。

## 2. 画面設計
### 2.1 作成条件エリア
- 対象月入力。
- 連続勤務が最大4日であることを表示。

### 2.2 必要人数エリア
- 0〜23時の時間帯別人数入力。

### 2.3 勤務体系登録エリア
- 入力項目: 名称、開始時刻、終了時刻、翌日公休の有無。
- 一覧表示: 勤務体系情報 + 削除ボタン。

### 2.4 勤務者登録エリア
- 入力項目: 勤務者名、勤務可能勤務体系（チェックボックス複数選択）、月間公休日数、対象月の希望休（日付チェックボックス複数選択）。
- 一覧表示: 勤務者名 + 対応勤務体系 + 月間公休日数 + 希望休 + 名前変更ボタン + 希望休編集ボタン + 削除ボタン。

### 2.5 テストパターン
- 作成条件エリアのボタンから、所定の勤務体系・勤務者・必要人数・公休日数を一括設定する。

### 2.6 勤務人数対象外時間登録エリア
- 入力項目: 担当者候補（チェックボックス複数選択）、日付、開始・終了の時と分（選択式）。
- 一覧表示: 勤務人数対象外条件 + 編集ボタン + 削除ボタン。

### 2.7 結果表示エリア
- 成功時: CSVと同じ、勤務者を行、日付を列とするシフト表。末尾列に勤務日数を表示。
- 成功時: ページ内のみ、日付を行、勤務時間帯を列とする勤務者表を併記。
- 勤務人数対象外の担当者は時間帯別勤務者表で対象外時間とともに強調表示。
- 外部ヘルプが必要な場合は、日付・開始終了時刻・人数・合計時間を表形式で表示。
- 代替案がある場合は、最大3個のパターン切替ボタンを表示。
- 失敗時: エラーメッセージ。
- 計算中: Web Workerから受け取った進行状況とキャンセルボタン。
- 成功時: CSVダウンロードボタン、Googleスプレッドシート出力ボタン。

## 3. データ設計
### 3.1 勤務体系
- `id`: 一意識別子。
- `name`: 勤務体系名。
- `startHour`: 開始時刻（0〜23）。
- `startMinute`: 開始分（0・15・30・45、省略時0）。
- `endHour`: 終了時刻（0〜23）。
- `endMinute`: 終了分（0・15・30・45、省略時0）。
- `breaks`: 勤務時間から除外する休憩時間配列。
- `nextDayOff`: この勤務体系を割り当てた翌日を公休にするか。

### 3.2 勤務者
- `name`: 勤務者名。
- `patternIds`: 勤務可能な勤務体系ID配列。
- `requiredDaysOff`: 月間公休日数。
- `requestedDaysOff`: 希望休の日番号配列。

### 3.3 シフト結果
- `success`: 成否フラグ。
- `month`: 対象月。
- `assignments[]`: 日別割当（`date`, `workers`, `shifts`, `statuses`, `temporaryAbsences`）。
- `helpRequests[]`: 外部ヘルプ（`date`, `startTime`, `endTime`, `count`）。
- `helpQuarterTotal`: 15分単位で集計した合計ヘルプ人時。

### 3.4 出力表
- 先頭行: `勤務者`、対象月の日付、`勤務日数`。
- データ行: 勤務者名、日付ごとの勤務体系名・`明`・`公`・`公休`のいずれか、月間勤務日数。`明`は勤務日数に含める。

## 4. 永続化設計
- 保存先: `localStorage`
- キー: `autoshiftmaker.patterns`
- 対象: 勤務体系配列

## 5. バリデーション方針
- 勤務体系名、勤務者名は必須。
- 勤務時間は0〜23時、分は0・15・30・45のいずれか。
- 勤務者は勤務可能勤務体系を1件以上選択必須。
- 希望休は対象月の日付とし、月間公休日数以下の件数とする。
- 必要人数は0以上の整数。

## 6. 例外・エラー時挙動
- 入力不正時は作成処理を中断し、エラー表示。
- 制限時間内に実行可能案を発見できない場合は失敗メッセージを表示。
- 登録担当者だけで必要人数を満たせないこと自体は失敗とせず、必要な外部ヘルプを結果へ表示。

## 7. シフト作成ルール設計
- ルールの正本は要件定義書「5.1 シフト作成ルール」とする。
- 勤務日と`明`を連続勤務として数え、4連勤を許可、5連勤を禁止する。
- `①`・`夜`・`③`の夜勤後マーカー、夜勤周期、勤務回数、禁止遷移を担当者単位で判定する。
- 必要人数、休憩、勤務人数対象外時間、外部ヘルプは15分単位で判定する。
- 要件を満たす案が複数ある場合は、安全に入れ替え可能な担当者から最大3案を構成する。
