# AutoShiftMaker 要件定義書

## 1. 目的
- 勤務体系・勤務者・必要人数条件をもとに、月次シフト表を自動作成する。
- シフト作成時の手作業を削減し、条件違反を抑止する。

## 2. 対象範囲
- ブラウザ上で動作する単一ページWebアプリ。
- 勤務体系登録、勤務者登録、シフト作成、結果表示を対象とする。

## 3. 利用者
- シフト作成担当者（管理者）。

## 4. 機能要件
### 4.1 勤務体系管理
- 勤務体系名、開始時刻、終了時刻、翌日公休の有無を登録できる。
- 登録済み勤務体系を一覧表示できる。
- 登録済み勤務体系を削除できる。
- 勤務体系はブラウザのローカルストレージに保存し、再訪時に再利用できる。

### 4.2 勤務者管理
- 勤務者名、勤務可能な勤務体系（複数）、月間公休日数、対象月の希望休（複数）を登録できる。
- 登録済み勤務者を一覧表示できる。
- 登録済み勤務者の名前を変更できる。
- 登録済み勤務者の希望休を変更できる。
- 登録済み勤務者を削除できる。
- 勤務体系削除時、その勤務体系のみを保持していた勤務者は一覧から除外する。

### 4.3 シフト条件設定
- 対象月（YYYY-MM）を指定できる。
- 0〜23時の各時間帯の必要人数を設定できる。
- ヘルプ・委員会活動などで勤務人数の対象外となる担当者候補（複数可）、日付、開始・終了時刻を登録できる。
- 登録した勤務人数対象外条件を編集・削除できる。

### 4.4 シフト自動作成
- 条件を満たす日別勤務割当を生成できる。
- 入力不備または制限時間内に実行可能案を発見できない場合はエラーメッセージを表示する。
- 登録勤務者だけで必要人数を満たせない場合は、制約を維持したまま外部ヘルプの合計時間を最小化し、必要な日付・時間帯・人数を表示する。
- 同一条件の勤務者を入れ替えた別解がある場合、同じ最小ヘルプ量のシフトを最大3案表示する。
- 生成結果はCSVと同じ、勤務者を行、日付を列とする表で勤務体系名または公休を表示する。
- 生成結果のページ内に、日付を行、勤務時間帯を列とする勤務者表を表示する。
- 月間公休日数を維持しながら、時間帯別必要人数を超える余剰配置が少ない勤務形態を優先する。
- 生成結果に勤務者ごとの勤務日数を表示する。

### 4.5 シフト出力
- 生成したシフトを、勤務者を行、日付を列、勤務体系または公休を値とする表へ変換できる。
- UTF-8のCSVファイルとしてダウンロードできる。
- Googleスプレッドシートへ貼り付け可能な形式でクリップボードへコピーし、新規シートを開ける。
- CSVとGoogleスプレッドシート用データに勤務者ごとの勤務日数を含める。

## 5. 業務ルール要件

### 5.1 シフト作成ルール

| ID | 分類 | ルール |
| --- | --- | --- |
| BR-01 | 1日内の割当 | 1人へ同じ日に複数の勤務体系を割り当ててはならない。`明`または`公`の日にも勤務を割り当ててはならない。 |
| BR-02 | 月間公休日数 | 各担当者の公休日数は、担当者登録で指定した月間公休日数と一致させる。`公`と通常の`公休`は公休日数に含め、`明`は含めない。 |
| BR-03 | 希望休 | 希望休には勤務を割り当ててはならない。希望休の日数は月間公休日数以下とする。 |
| BR-04 | 連続勤務 | 勤務日と`明`を連続勤務日として数え、連続勤務は最大4日とする。4連勤は許可し、5日以上の連続勤務は禁止する。`公`と`公休`で連続勤務をリセットする。 |
| BR-05 | ①勤務後 | `①`の翌日は`明`、その翌日は`公`とする。`明`は勤務日数および連続勤務日数へ含める。 |
| BR-06 | 夜勤務後 | `夜`の翌日は`明`、その翌日は`公`とする。`明`は勤務日数および連続勤務日数へ含める。 |
| BR-07 | ③勤務後 | `③`の翌日は`明`とする。その翌日の`公`は必須としない。 |
| BR-08 | 翌日公休設定 | 勤務体系で「翌日を公休にする」が有効な場合、勤務開始日の翌日は`公`とする。ただし、`①`・`夜`はBR-05・BR-06を優先する。 |
| BR-09 | 夜勤回数 | 夜勤を`①`・`夜`・`③`と定義する。夜勤、必要な`明`、必要な`公`を1回の夜勤周期として数え、夜勤周期は2回まで連続可、3回連続は禁止する。 |
| BR-10 | 勤務回数の均衡 | 担当者ごとに、対象月の`M`・`R`・`L`の合計回数を`①`の回数と一致させる。 |
| BR-11 | M/R/Lの連続禁止 | `M`・`R`・`L`のいずれかの翌日に、`M`・`R`・`L`のいずれかを割り当ててはならない。 |
| BR-12 | 勤務遷移禁止 | `E→D`・`M→D`・`E→A`・`E→R`・`M→A`・`E→L`の連続割当を禁止する。 |
| BR-13 | 必要人数 | 各15分枠の勤務人数は、画面で時間帯ごとに指定した必要人数を下回ってはならない。勤務体系の休憩時間は勤務人数へ含めない。 |
| BR-14 | 余剰配置 | 月間公休日数など他のルールを守る範囲で、必要人数を超える余剰配置が少ない勤務体系を優先する。 |
| BR-15 | 勤務人数対象外時間 | 対象者は出勤日・勤務日数として扱うが、指定時間だけ勤務人数へ含めない。候補が複数の場合は、当日その時間に勤務する候補から1人を選ぶ。 |
| BR-16 | 外部ヘルプ | 登録担当者だけでBR-13を満たせない場合も他のルールを緩和せず、外部ヘルプを追加する。外部ヘルプは人数を加味した15分枠の合計が最小となる案を採用する。 |
| BR-17 | 代替案 | 同一の勤務可能体系・月間公休日数・希望休・勤務人数対象外条件を持つ担当者を入れ替えて別解を作れる場合、同じ最小ヘルプ量の案を最大3件表示する。 |

### 5.2 テストパターン
- 指定済みの勤務形態、勤務者、時間帯別必要人数、公休日数を一括で読み込めること。
- 勤務形態は `D`, `R`, `M`, `E`, `P`, `P2`, `B`, `短`, `③`, `①`, `夜`, `A`, `C`, `E半`, `半E`, `D半`, `半D`, `A短`, `L` とする。
- `③` は22時〜翌7時で翌日公休なし、`①` は17時30分〜翌9時30分で翌日公休、`夜` は17時15分〜翌11時15分かつ9〜10時を休憩とし翌日公休とする。
- `L` は7時〜18時勤務とする。
- 分単位の勤務開始・終了と休憩は15分単位で必要人数判定へ反映する。
- 勤務者は1さん〜10さんとし、5さん・6さんは月12日、それ以外は月9日の公休とする。

## 6. 非機能要件
- 最適化計算はWeb Workerで実行し、画面の応答を妨げないこと。
- 計算中は進行状況とキャンセル操作を表示すること。
- 最適化処理はブラウザ内のWebAssemblyで完結し、GitHub Pagesで公開可能であること。
- クライアントサイドJavaScriptのみで動作すること。
- モダンブラウザで利用できること。
- 入力不備時は利用者が理解できる日本語メッセージを表示すること。

## 7. 制約・前提
- 永続化対象は勤務体系のみ（ローカルストレージ）。
- 勤務者データはページ再読込で初期化される。
- 外部サーバー連携は行わない。
