# AutoShiftMaker

自動でシフト表を作成するシンプルな Web アプリです。

## 使い方

1. `index.html` をブラウザで開く
2. 勤務体系（勤務時間・翌日公休の有無）を登録する（不要な勤務体系は削除可能）
3. 勤務者名、勤務可能な勤務体系（複数選択可）、月間公休日数、希望休を登録する（登録後の希望休編集・不要な勤務者の削除が可能）
4. 対象月と時間ごとの必要人数を設定する
5. 「シフト表を作成」を押す
6. 作成結果からCSVをダウンロードするか、Googleスプレッドシート用の表をコピーする

登録済み勤務者の「名前変更」から、勤務条件を残したまま氏名を修正できます。

「テストパターンを読み込む」を押すと、D・R・M・E・P・P2・B・短・③・①・夜・A・C・E半・半E・D半・半D・A短・Lの勤務形態、1さん〜10さん、時間帯別必要人数、公休日数がまとめて入力されます。Lは7〜18時勤務です。勤務時間は15分単位で判定し、「夜」の9〜10時は休憩として必要人数へ加算しません。

## シフト表を出力する

- 「CSVをダウンロード」を押すと、`autoshift-YYYY-MM.csv` をUTF-8形式で保存します。
- 「Googleスプレッドシートへ出力」を押すと、新しいGoogleスプレッドシートを開き、担当者別のシフト表をクリップボードへコピーします。新しいシートのA1セルへ貼り付けてください。
- 画面、CSV、Googleスプレッドシートには、担当者を行、日付を列とする同じシフト表を表示し、各担当者の勤務日数も出力します。
- `①`と`夜`の翌日は`明`、その翌日は`公`とします。`③`は翌日のみ`明`とします。`明`は勤務日数に含め、公休数には含めません。
- 夜勤（`①`・`夜`・`③`）は2連続まで、`M`・`R`・`L`の合計回数は`①`の回数と一致させます。
- `M`・`R`・`L`同士の連続と、`E→D`・`M→D`・`E→A`・`E→R`・`M→A`・`E→L`を禁止します。
- ページ内には、CSVと同じ表に加えて、日付ごと・時間帯ごとの勤務者表も表示します。
- 登録者だけでは条件を満たせない場合、必要な外部ヘルプを15分単位で最小化し、日付・時間帯・人数と合計時間を表示します。
- 条件が同じ担当者を安全に入れ替えられる場合、同じ最小ヘルプ量のシフトを最大3パターン表示します。
- 計算はHiGHS WebAssemblyをWeb Worker内で実行するため、計算中も画面操作とキャンセルが可能です。外部の計算サーバーや従量課金APIは使用しません。
- ヘルプ・委員会活動などの勤務人数対象外時間では、担当者候補（複数可）・日付・15分単位の時間を登録でき、登録後の編集・削除にも対応します。対象者は出勤日・勤務日数として扱いますが、その時間だけシフト上の必要人数から除外します。複数候補の場合は、シフト作成時に出勤者から1人を選択します。
- ポップアップやクリップボードがブロックされた場合は、CSVをダウンロードしてGoogleスプレッドシートの `ファイル > インポート` から読み込めます。

## スマホで動作確認する

PCとスマホを同じWi-Fiへ接続し、PCで次のコマンドを実行します。

```bash
npm run dev
```

表示された `スマホ: http://<PCのIPアドレス>:4173` をスマホのブラウザで開いてください。Windows Defender ファイアウォールの確認が表示された場合は、プライベートネットワークでのNode.jsの通信を許可します。

接続できない場合は、次を確認してください。

- PCとスマホが同じネットワークに接続されている
- ゲストWi-Fiなど、端末間通信を禁止するネットワークを使用していない
- Windows Defender ファイアウォールでNode.jsのプライベートネットワーク通信が許可されている

サーバーを終了するには、PCのターミナルで `Ctrl+C` を押します。

## 仕様

- 勤務体系は登録後に再利用できます（ブラウザの `localStorage` に保存）
- 勤務体系を削除すると、その勤務体系だけに紐づく勤務者は登録一覧から削除されます
- 勤務体系で「翌日を公休にする」を選択すると、その勤務を開始した翌日には同じ勤務者を割り当てません
- 勤務者ごとに指定した月間公休日数と一致するように割り当てます
- 担当者登録で選択した希望休には勤務を割り当てません。希望休は登録後も変更できます
- 公休日数を維持したうえで、必要人数を超える余剰配置が少ない勤務形態を優先します
- 連続勤務は最大4日とし、5日以上連続では割り当てません
- 登録者だけでは成立しない場合は、成立に必要な外部ヘルプを日付・時間帯・人数で表示します
- 同じ条件で別案を作れる場合は、最大3パターンを切り替えて確認できます

## テスト

テストの実行には Node.js 18 以上が必要です。最初に依存パッケージをインストールしてください。`npm install` 時にHiGHSのブラウザ用ファイルも `vendor/highs` へ同期されます。

```bash
npm install
npm test
```

## GitHub Pagesで公開する

このアプリはHiGHS WebAssemblyを含む静的ファイルだけで動作するため、GitHub Pagesを使うとサーバーを別途用意せずに公開できます。最適化計算はWeb Worker内で実行され、サーバーAPIや従量課金サービスは使用しません。

1. GitHubのリポジトリで `Settings > Pages` を開く
2. `Build and deployment` の `Source` を `GitHub Actions` に設定する
3. `main` ブランチにpushすると、`.github/workflows/deploy-pages.yml` が自動的にビルド・公開を行う
4. 公開後に表示されるURL（例: `https://<ユーザー名>.github.io/<リポジトリ名>/`）へアクセスする

公開後は `Actions` タブでデプロイ状況を確認できます。データはブラウザの `localStorage` に保存されるため、端末ごとに保存内容が分かれます。
