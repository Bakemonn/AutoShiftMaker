# AutoShiftMaker

自動でシフト表を作成するシンプルな Web アプリです。

## 使い方

1. `index.html` をブラウザで開く
2. 勤務体系（週の勤務回数・勤務時間）を登録する（不要な勤務体系は削除可能）
3. 勤務者名、勤務可能な勤務体系（複数選択可）、月間公休日数を登録する（不要な勤務者は削除可能）
4. 対象月、時間ごとの必要人数、連続勤務日数上限を設定する
5. 「シフト表を作成」を押す

「テストパターンを読み込む」を押すと、D・R・M・E・1・P・P2・B・短の勤務形態、1さん〜10さん、時間帯別必要人数、公休日数がまとめて入力されます。

## スマホで動作確認する

PCとスマホを同じWi-Fiへ接続し、PCで次のコマンドを実行します。

```bash
npm run dev
```

表示された `スマホ: http://<PCのIPアドレス>:4173` をスマホのブラウザで開いてください。Windows Defender ファイアウォールの確認が表示された場合は、プライベートネットワークでのNode.jsの通信を許可します。

接続できない場合は、次を確認してください。

- PCとスマホが同じネットワークに接続されている
- ゲストWi-Fiなど、端末間通信を禁止するネットワークを使用していない
- Windows Defender ファイアウォールでNode.jsのプライベートネットワーク通信が許可されている

サーバーを終了するには、PCのターミナルで `Ctrl+C` を押します。

## 仕様

- 勤務体系は登録後に再利用できます（ブラウザの `localStorage` に保存）
- 勤務体系を削除すると、その勤務体系だけに紐づく勤務者は登録一覧から削除されます
- 夜勤（開始時刻 >= 終了時刻）の場合、`18日〜19日` の勤務後は `20日` を休みにします
- 勤務者ごとに指定した月間公休日数と一致するように割り当てます
- 条件を満たせない場合は失敗メッセージを表示します

## テスト

テストの実行には Node.js 18 以上が必要です。依存パッケージのインストールは不要です。

```bash
npm test
```

## GitHub Pagesで公開する

このアプリは静的ファイル（`index.html` / `app.js` / `scheduler.js`）のみで動作するため、GitHub Pagesを使うとサーバーを別途用意せずに公開できます。

1. GitHubのリポジトリで `Settings > Pages` を開く
2. `Build and deployment` の `Source` を `GitHub Actions` に設定する
3. `main` ブランチにpushすると、`.github/workflows/deploy-pages.yml` が自動的にビルド・公開を行う
4. 公開後に表示されるURL（例: `https://<ユーザー名>.github.io/<リポジトリ名>/`）へアクセスする

公開後は `Actions` タブでデプロイ状況を確認できます。データはブラウザの `localStorage` に保存されるため、端末ごとに保存内容が分かれます。
